# Source packages

`ltm/` is the product-foundation package. It owns the numeric FieldIR v2
contracts, codec, source-archive split, and canonical intake adapters. Under
the current architecture, FieldIR v2 is the implemented packed execution
bridge derived from the exact semantic substrate.

`ltm_r2/` is the isolated validated Mumbrane IR v1 candidate. It is the
canonical future compiler target, but it is not yet promoted into `ltm/`.

`topology_g*` and `micro_ltm*` are immutable historical experiment packages.
Their import names and commands are public research interfaces; names such as
`topology_g21`, `topology_g210`, and `topology_g101` are intentionally retained.
They are evidence and controls, not competing product runtime formats.

`ltm_inference_i*` packages are isolated latent-inference studies. In
particular, `ltm_inference_i31/` implements the development-only mathematical
reality prototype: bounded body retrieval, learned action guidance, exact proof
application, reality isolation, and independent replay. It is not part of the
canonical product execution path and has no locked pass.

`ltm_limit_l1/` measures that frozen I3.1 prototype. It is a capacity study,
not a product runtime: it observed verified depth through 64 on grounded formal
rewrite and opaque traversal panels. The exact boundary and statistical caveat
are recorded in the [architecture lock](../docs/architecture/architecture-lock-v1.md).

`ltm_limit_l4/` is the isolated branching-proof experiment. It adds a signed
39-schema executable bank, exact proposal enumeration, a compact proposal/value
kernel and evaluator-separated replay. It failed its pre-lock proposal-learning
gate and is not an adopted runtime component.

The machine-readable ownership and status index is
[`docs/experiments/registry.json`](../docs/experiments/registry.json). New
organization must update that registry instead of renaming historical packages.
