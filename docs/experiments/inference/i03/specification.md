# I3 — Goal-Conditioned Multiscale Latent Inference

**Status:** development-control stop. I3 is a separate latent-guided exact
mathematical proof-search experiment. Its current rewrite fragment validates
exact replay, but does not establish a goal-conditioned energy mechanism; no
locked suite is authorized.

## Objective

I2.2 tests terminal completion: an initial supplied Mumbrane moves through source-backed observed transitions until no further transition is available. It contains no representation of a user’s requested target.

I3 must answer the next question: given the same prompt evidence but different supplied goal Mumbranes, can a bounded multiscale latent field recover the correct source-backed terminal, intermediate, negative, or unknown target without relation labels, named roles, closure, supplied answer IDs, or query-specific routing hints?

A passing I3 would support goal-conditioned, source-backed formal mathematical
proof candidates only. It would not authorize factual writes, replace G6/G9,
establish raw-language compilation, or demonstrate unrestricted reasoning.

## Implemented first boundary

The first runnable I3 fragment uses a frozen 46-schema exact rewrite bank over
equality, ring, order, modular, finite-set and propositional expressions. A
small learned scorer ranks applicable schemas; the exact kernel performs each
rewrite and evaluator-only code replays a returned proof. Training and
development data are generated by expanding known-valid goals backwards, then
requiring the runtime to simplify them forwards.

The first development run is deliberately not a result classification. Its
controls are testing whether this is genuinely a latent-energy mechanism rather
than merely learned axiom ranking plus exact rewriting. See the measured
[I3 report](report.md).

## Assumptions

1. The first I3 boundary receives supplied atomic Mumbranes for prompt evidence and requested goal; raw text compilation is diagnostic.
2. A goal is a requested semantic state/property, not an answer candidate or requested hop count.
3. Observed transition bodies remain anonymous: no relation names, roles, proof depths, closure, or origin-to-terminal maps at runtime.
4. An accepted result must be supported by opened bodies and abstain when no certified path reaches the goal within budget.
5. I2.2’s deterministic learned-vector tree is a historical baseline only. I2.3 must establish evaluator isolation, non-regular graph composition, and a genuine field law before I3 begins.

## Authoritative flow

prompt-evidence Mumbranes plus goal Mumbrane
→ shared aligned projection
→ immutable evidence anchor and immutable goal anchor
→ global content-addressed minimap descent
→ bounded detailed frontier
→ movable inference state plus candidate activations
→ projected energy updates and frontier reopening
→ source-backed candidate, ambiguity, or unknown
→ evaluator-only exact comparison

The evidence anchor never changes. The goal anchor biases retrieval and stopping but cannot identify an answer body or bypass source-backed transitions.

## Dataset requirement

The decisive suite must use identical initial evidence under several different goals. For example, with observed transitions seed to sprout to plant to flowering and seed to food:

- goal flowering must return flowering;
- goal plant must return plant;
- goal not-food must abstain or return only a source-backed negative;
- goal dormant must be available only under fictional scope.

The generator must enforce split-disjoint entities, semantic combinations, paths, goals, scopes, and body compositions. No body may contain the initial state and requested answer for depths above one. The runtime receives no answer candidate, answer-specific body identifier, or depth signal. The evaluator owns an independent direct semantic oracle.

## Controls and interventions

1. Remove the goal anchor: same-evidence/different-goal accuracy must decline materially.
2. Replace a goal with a semantically near but incorrect goal: the candidate must change or abstain.
3. Keep evidence fixed and swap two goals: the results must swap accordingly.
4. Remove a decisive intermediate body: the answer must change or become unknown.
5. Alter an irrelevant region: the semantic result must remain invariant.
6. Randomize goal vectors: performance must collapse, otherwise a goal-independent shortcut exists.
7. Compare deterministic tree routing against learned summaries only with identical access budgets.
8. Corrupt scope/time on a decisive body: the result must abstain rather than cross the boundary.

## Testing and boundaries

- Always: preserve I2.2 as frozen baseline, use paired evaluator comparisons, fail closed, record exact frontier provenance, and run repository checks.
- Ask first: add dependencies, modify G1/G6/G9 schemas, change Mumbrane representation, or make a latent candidate factual.
- Never: supply answer candidates/depth/closure, scan the full field, use relation labels or named roles, train on locked data, or overwrite I2.2 artifacts.

Unit tests cover forbidden prompt fields, goal/evidence separation, anchor immutability, energy descent, bounded frontier access, and scope/time gates. Generator tests cover no answer leakage and same-evidence/different-goal validity. Locked evaluation must be evaluator-separated and replayable.

## Interpretation

A pass would show that I2.2’s movable latent state can be task-conditioned instead of only terminal-completion conditioned. A failure must identify whether the issue is goal separation, goal-conditioned retrieval, state dynamics, safety/coverage, or generator leakage.

This proposal intentionally authorizes no implementation until its assumptions and gates are reviewed.
