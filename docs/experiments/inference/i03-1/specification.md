# I3.1 — Branching Mathematical Reality Search

**Status:** development implementation. No locked result is authorized.

I3.1 corrects I3’s globally exposed rewrite bank. Every proof action must
originate in one of at most 64 retrieved, reality-scoped mathematical bodies.
The learned kernel ranks body applications and estimates remaining proof cost;
the exact equality kernel replays every accepted proof.

The current development corpus pairs the same source with two different goals,
contains 32 legal first actions, and stores later proof hops in separate indexed
regions. This makes removal of the goal or dynamic frontier reopening a causal
test rather than a cosmetic ablation.

The next required boundary is a cost-to-go and detour corpus. The current
remaining-cost head is intentionally not treated as validated until its removal
degrades bounded proof search.

The `freeze` lifecycle command enforces this boundary mechanically: it refuses
to authorize locked evaluation unless goal, action-scoring, frontier and
remaining-cost causal controls all pass.

The next corpus revision must remove public route-position labels and the
reduction preference from the detour panel. It will retain only query-
independent cell membership, generic state/body vectors, reality keys and
exact body ASTs at runtime; evaluator-only shortest-distance labels train and
evaluate remaining-cost guidance.

Each minimap cell now stores at most eight anonymous transition-direction
modes, an entrance centroid and uncertainty derived from member bodies. These
are query-independent summaries of local source material; they may guide
opening but may not contain an answer list, proof route, remaining proof cost
or transitive closure.

The detour revision begins with opaque equality fixtures containing a shortest
3-hop path, a longer valid path and 22 dead-end alternatives. An evaluator-only
graph oracle supplies shortest-distance labels for training and measurement;
those labels never enter public bodies, runtime vectors, minimap cells or
problems.

The bounded content index now has a generic exact-source posting as well as
optional semantic component postings. It maps a current formal state to bodies
whose left-hand side is that state; it stores neither a target, a proof route,
nor a closure. This is the operational field address used before learned action
ranking and exact application.

The same field also maintains a reverse exact-target posting for bounded
bidirectional proof search. It maps only a local target expression to immediate
predecessor bodies; exact search constructs any multi-hop connection at request
time.
